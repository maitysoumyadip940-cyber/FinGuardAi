# FinGuard AI API Reference

Base URL locally:

```text
http://127.0.0.1:8000
```

Production:

```text
https://YOUR-PROJECT.vercel.app
```

## GET /api/health

Checks that the API is running and the transaction dataset loaded.

## GET /api/transaction/{utr}

Returns one transaction by exact UTR.

Example:

```text
GET /api/transaction/UTR26082400001107
```

Returns HTTP 404 if the UTR is not present.

## GET /api/search

Searches transactions using optional filters.

Example:

```text
GET /api/search?risk=HIGH&method=UPI&state=Delhi&min_amount=40000&limit=10
```

### Query parameters

- `label`: Fraud or Genuine
- `risk`: LOW, MEDIUM, HIGH
- `method`: UPI or Card
- `state`: state name
- `city`: city name
- `min_amount`: minimum INR amount
- `max_amount`: maximum INR amount
- `min_risk`: minimum score
- `max_risk`: maximum score
- `limit`: 1–100 results

## GET /api/stats

Returns aggregate dataset statistics.

## GET /api/alerts

Paginated, most-urgent-first feed of transactions that crossed the review
threshold — the working queue behind the Allow / Flag / Block decision step.

Example:

```text
GET /api/alerts?min_risk=85&state=Bihar&limit=10
```

### Query parameters

- `min_risk`: lowest risk score to include (default `70`, i.e. HIGH)
- `payment_method`: UPI or Card
- `state`: state name
- `limit`: 1–200 results
- `offset`: pagination offset

Each alert includes a `decision` field: `BLOCK` at risk ≥ 85, otherwise `FLAG`.

## GET /api/alerts/{utr}

Returns a single alert by UTR. Returns HTTP 404 if the UTR is not present,
or if it was never flagged (risk score below 30).

## GET /api/alerts/reasons

Aggregated counts of `Fraud_Risk_Reason` among flagged transactions — powers
a "top reasons we're flagging transactions" chart.

Example:

```text
GET /api/alerts/reasons?min_risk=85&top=5
```

## GET /api/alerts/docs

Swagger UI for the alerts API.

## GET /api/docs

Swagger UI generated by FastAPI.

## GET /api/redoc

ReDoc API documentation.

## Response fields

The transaction response preserves the dataset's original fields and adds:

```json
{
  "Risk_Level": "HIGH"
}
```

The API does not modify the original transaction dataset.
